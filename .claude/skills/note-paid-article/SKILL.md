# note 有料記事執筆スキル（ラグジュアリー購入記）

エルメスやロレックスを正規店で購入していく過程を、note の有料記事として書くためのスキル。

読者はお金を払って「この人にしか書けない具体的な話」を読みに来る。だから記事の価値は、(1) 書き手本人の実体験の具体性と、(2) 事実の正確さの2本柱で決まる。きれいな文章よりも、この2つを優先する。

## 全体の流れ

1. ヒアリング（体験メモを集める）
2. 調査・事実確認
3. 構成（無料部分／有料部分の設計）
4. 執筆
5. 推敲（自然な日本語にする）
6. 公開前チェック → 納品

依頼が「推敲だけ」「タイトルだけ」なら該当ステップから始めてよい。

---

## 1. ヒアリング

体験記の核になるのは書き手の記憶。足りない情報は書き始める前に質問して集める。一度に聞きすぎず、重要なものから5問程度まで。

集めたい情報:
- いつ・どの店舗（地域レベルでよい）に行ったか、何回目の来店か
- 担当者とのやり取り（印象に残った一言、聞かれた質問、自分の答え）
- 実際に買ったもの・提案されたもの・断ったもの、その金額
- そのときの感情（緊張、落胆、嬉しさ）と、あとから気づいたこと
- 読者に一番伝えたいこと（この記事のゴール）

**体験は絶対に創作しない。** 有料記事で作り話の体験を売ると読者を欺くことになり、発覚すれば書き手の信用も失う。情報が足りない箇所は `【要記入：〇〇店での担当者の第一声】` のように空欄にして渡し、書き手に埋めてもらう。それらしい会話やエピソードを補完したくなっても、空欄のままにするのが正解。

## 2. 調査・事実確認

記事に出てくる「事実」は、書く前に調べて裏を取る。具体的な調べ方と情報源の優先順位は `references/research-guide.md` を読むこと。

要点:
- 定価・価格改定・購入制限・販売方針は頻繁に変わる。記憶や古い記事で書かず、Web検索（WebSearch / TinyFish など使えるツール）で最新情報を確認する
- 数字や制度には「2026年10月時点」のように時点を添える
- 確認できなかったことは断定しない。「〜と言われています」「私の担当者は〜と言っていました」のように、根拠の種類が分かる書き方にする
- 噂（「◯◯万円買えばバーキンが出る」等）は、噂であると明示したうえで自分の体験と照らして書く。これは読者が一番知りたい部分でもあるので、避けずに誠実に扱う
- 調べた内容と出典URLは、記事とは別に「調査メモ」として書き手に渡す

## 3. 構成

note の有料記事は「無料部分で信頼と期待をつくり、核心を有料にする」形にする。詳しい型とタイトルの付け方は `references/structure.md` を読むこと。

基本形:

```
タイトル
【無料部分】
  リード（この記事で何が分かるか・誰向けか）
  自己紹介（購入実績を簡潔に＝信頼の根拠）
  体験の導入〜山場の手前
  有料部分の目次（何が読めるかを具体的に）
――――― ここから有料 ―――――
【有料部分】
  具体的な手順・会話・金額・時系列
  うまくいかなかったこと・失敗談
  再現するためのポイント
  まとめ
```

無料部分は全体の3〜4割が目安。無料部分だけでも「読んでよかった」と思える内容にしつつ、一番具体的な情報（金額、会話の中身、手順）は有料側に置く。

## 4. 執筆

- 文体は **です・ます調**。親しみはあるが馴れ馴れしくない、落ち着いた大人の語り口
- 一人称は「私」（書き手から指定があればそれに従う）
- 抽象的な形容（「洗練された空間」「特別な体験」）より、具体的な場面（「入口でドアマンに名前を聞かれ、ソファで15分待ちました」）を書く
- 数字・時間・金額・回数をできるだけ入れる。読者が有料で買っているのは具体性
- 感情の揺れを正直に書く。成功体験だけの記事は信用されにくく、失敗や迷いが記事の説得力になる
- 断定と推測を区別する。体験は言い切り、一般論は根拠を添える

## 5. 推敲（自然な日本語）

書き上げたら、AIが書いたように見える癖を取り除く。具体的な NG 表現と言い換えは `references/natural-japanese.md` にあるので必ず読むこと。

機械的なチェックには付属スクリプトを使う:

```bash
python3 <このスキルのディレクトリ>/scripts/check_ai_phrases.py 記事.md
```

ヒットした箇所を見直す。ただしスクリプトは目安で、文脈上自然なら残してよい。最後に記事全体を書き手になったつもりで音読するように読み、「この人はこういう言い方をしないな」と感じる箇所を直す。

## 6. 公開前チェック

`references/checklist.md` の項目を確認する。特に:
- 体験の創作がないか（【要記入】が残っていれば、書き手に埋めてもらう必要があることを伝える）
- 価格・制度に時点と根拠があるか
- 店舗スタッフ個人が特定できる書き方になっていないか
- 転売を勧める内容になっていないか
- アフィリエイトリンクや提供品がある場合、冒頭に PR 表記があるか（ステマ規制）

## 納品フォーマット

次の順でまとめて渡す:

1. **タイトル案** 3つ（それぞれの狙いを一言）
2. **本文**（note にそのまま貼れる Markdown。見出しは `##` と `###` のみ。有料ラインは `――――― ここから有料 ―――――` と書き、note エディタで有料ラインを設定するよう添える）
3. **価格の目安**（文字数・情報の希少性から。note では 300〜3,000円帯が多い）
4. **ハッシュタグ案** 5〜8個
5. **調査メモ**（確認した事実・出典URL・確認日）
6. **書き手に確認してほしいこと**（【要記入】箇所、推測で書いた箇所の一覧）
